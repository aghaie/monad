# طراحی: موتور خودتفسیر قرآن — به‌مثابه سکوی توسعه‌پذیر

> سند طراحی (spec). تاریخ: ۱۴۰۵/۰۴/۰۲ (۲۰۲۶-۰۶-۲۳).
> برآمده از جلسه‌ی brainstorming. وضعیت: تأییدشده، آماده‌ی نوشتن نقشه‌ی اجرا.

## ۱) هدف و چارچوب

ساختِ **موتور خودتفسیر قرآن**: ابزاری که نشان می‌دهد قرآن چگونه خودش را از خودش
توضیح می‌دهد — کاربر یک آیه را می‌بیند و آیه‌های روشن‌گرش (با شاهدِ ریشه‌های مشترک) را
کشف می‌کند. این موتور **اولین ماژولِ یک سکو** است؛ ایده‌های دیگرِ
[`docs/چه-میتوان-ساخت.md`](../../چه-میتوان-ساخت.md) بعداً همچون ماژول به همین سکو
افزوده می‌شوند.

### قیدِ بنیادینِ صداقت (از قانون اساسی پروژه)
موتور **فقط شاهد نشان می‌دهد، معنا نمی‌سازد**: کدام آیه‌ها یک آیه را روشن می‌کنند و
*چرا* (ریشه‌های مشترک، وزنِ رابطه). هیچ معنای بیرونی، ترجمه یا تفسیری افزوده نمی‌شود؛
خواندنِ معنا بر عهده‌ی انسان است. همه‌ی داده از خودِ متن و ایندکس‌های تأییدشده می‌آید.

### قالب و قلب تجربه (تصمیم‌های تأییدشده)
- قالب: **وب‌اپ تعاملیِ محلی**.
- قلب تجربه: **نقشه‌ی شبکه (گراف)**، گره‌خورده به یک **پنل شاهد** برای مطالعه‌ی عمیق.
- رویکرد معماری: **سرور API محلیِ پایتون + رابط SPA با رجیستریِ ماژول** (رویکرد «الف»).

## ۲) معماری کلان

دو بخش، با مرزِ روشن میان «سکو» (بازاستفاده‌پذیر) و «ماژول» (هر ایده):

```
app/
  server/                      # بک‌اند FastAPI (فقط‌خواندنی)
    main.py                    # اپ + ثبت خودکار روترِ ماژول‌ها از modules/
    data/
      db.py                    # اتصال فقط‌خواندنی به generated/monad.db
      indexes.py               # بارگذاری تنبلِ ایندکس‌های JSON تولیدشده
    services/                  # سرویس‌های مشترکِ بازاستفاده‌پذیر (هسته‌ی سکو)
      verses.py                # آیه، توکن‌ها، ریشه/لِما/صرف
      network.py              # خودتفسیر: روشن‌گرها + ریشه‌های مشترک
      communities.py           # ساختار گراف: سوره‌ها، یال‌ها، چیدمان
    modules/
      __init__.py              # MODULE_REGISTRY — فهرست روترها
      self_interpret.py        # ★ ماژول ۱
  web/
    index.html
    src/
      shell/                   # پوسته‌ی سکو
        registry.js            # رجیستریِ ماژول‌های فرانت
        layout.js              # نوار کناری + بومِ اصلی + مسیریابی
      lib/                     # ابزارهای مشترک
        api.js                 # کلاینت API
        verse.js               # رندرِ آیه + هایلایت ریشه
        root-chip.js
      modules/
        self-interpret/        # ★ ماژول ۱
          index.js             # ثبت در رجیستری: {id,title,icon,mount}
          graph.js             # گرافِ Sigma.js (سه ترازِ LOD)
          evidence-panel.js    # پنل شاهد
build/
  build_evidence_index.py      # بازتولید شاهدِ کامل برای هر ۶۲۳۶ آیه
  validate_evidence_index.py   # وارسیِ بازتولیدپذیری + جفت‌های مرجع
  build_graph_layout.py        # چیدمان از پیش‌محاسبه‌شده‌ی گراف (قطعی)
```

### قراردادِ ماژول (کلید توسعه‌پذیری)
افزودن هر ایده‌ی آینده = دقیقاً دو افزودنی، بدون دست‌زدن به هسته:
1. **بک‌اند:** یک فایل روتر در `server/modules/` که در `MODULE_REGISTRY` ثبت می‌شود؛
   `main.py` همه‌ی روترهای رجیستری را خودکار سوار می‌کند.
2. **فرانت:** یک ماژول در `web/src/modules/<name>/index.js` که خود را با
   `{id, title, icon, mount(container, api)}` در `shell/registry.js` ثبت می‌کند؛ پوسته
   آن را خودکار در نوار کناری فهرست می‌کند.

ماژول‌ها **داده را مستقیم لمس نمی‌کنند**؛ فقط از `services/*` (بک‌اند) و کلاینت `api.js`
(فرانت) استفاده می‌کنند. این تضمین می‌کند منطقِ تأییدشده‌ی دسترسی به داده یک‌جا و یکتا
بماند.

## ۳) لایه‌ی داده و API

منابع داده (همه موجود، فقط‌خواندنی):
- `generated/monad.db` — متن، توکن‌ها، ریشه‌ها، صرف.
- `generated/layers/L7_global/crossref_index.json` — روشن‌گرهای رتبه‌بندی‌شده.
- `generated/layers/L6_network/ayah_network.json` — یال‌های شبکه.
- `generated/layers/L7_global/global_structure.json` — ساختار سراسری/جامعه‌ها.
- `generated/layers/L8_interpret/evidence_index.json` — **(جدید، از گام ساخت)** شاهدِ
  کامل با ریشه‌های مشترک برای هر آیه.

نقاطِ پایانیِ API نسخه ۱:

| متد | مسیر | خروجی |
|---|---|---|
| GET | `/api/modules` | فهرست ماژول‌های فعال (برای نوار کناری) |
| GET | `/api/verse/{s}:{a}` | متن (۴ رسم‌الخط) + توکن‌ها با ریشه/لِما/صرف |
| GET | `/api/interpret/{s}:{a}` | `[{ayah, weight, cross_sura, shared_roots:[{ar,bw,count}]}]` رتبه‌بندی‌شده |
| GET | `/api/graph/communities` | `{nodes:[سوره...], edges:[وزنِ بینا‌سوره‌ای...]}` + مختصاتِ چیدمان |
| GET | `/api/graph/sura/{s}` | گره‌های آیه‌ی سوره + یال‌های درون‌سوره‌ای |

`shared_roots` هیچ glossِ بیرونی ندارد؛ فقط شکلِ عربی/باک‌والترِ ریشه و بسامدش — شاهد،
نه معنا.

## ۴) گام ساخت — قلب صداقت

`build/build_evidence_index.py`:
- برای **هر ۶٬۲۳۶ آیه** (نه فقط نمونه‌های L8)، آیه‌های روشن‌گر و **ریشه‌های مشترکِ
  توجیه‌گرِ هر پیوند** را محاسبه می‌کند.
- **با دقیقاً همان روشِ تأییدشده‌ی `scripts/build_L8_interpret.py`** (وزن‌دهیِ idf به
  ریشه‌های کمیابِ مشترک، با کنترلِ نشتِ موجود). منطق مشترک از همان مسیر بازاستفاده
  می‌شود تا «پدیده‌ی تأییدشده» دست‌نخورده بماند؛ فقط برای همه‌ی آیات مادی‌سازی می‌شود.
- خروجی: `generated/layers/L8_interpret/evidence_index.json`.

`build/build_graph_layout.py`:
- چیدمانِ نیرویِ گراف را یک‌بار و **به‌صورت قطعی** (دانه‌ی ثابت، بدون
  `random`/`Date.now`) محاسبه و ذخیره می‌کند، تا بارگذاری فوری و بازتولیدپذیر باشد.

`build/validate_evidence_index.py`:
- بازتولیدِ **بایت‌به‌بایت یکسان** را بررسی می‌کند (انضباط فاز).
- جفت‌های مرجعِ CLAUDE.md را وارسی می‌کند: ۲:۲۵۵↔۷:۹۷ (نوم)، ۲۴:۳۵↔۷:۱۳۷
  (شرق/غرب)، ۳:۷↔۹:۱۱۷ (زیغ) باید حاضر باشند.

## ۵) تجربه‌ی گراف (سه ترازِ بزرگ‌نمایی)

1. **صورت‌فلکی (صفحه‌ی نخست):** ۱۱۴ سوره همچون گره؛ اندازه ∝ تعداد آیه؛ چیدمانِ
   از‌پیش‌محاسبه‌شده؛ یال = مجموعِ وزنِ تفسیرِ بینا‌سوره‌ای. تجسمِ یافته‌ی «سوره‌ها
   جامعه‌اند».
2. **نمای سوره:** کلیک روی سوره → گره‌های آیه‌اش باز می‌شوند؛ یال‌های درون‌سوره‌ای
   (چگالی، تمرکز ~۳ برابری را نشان می‌دهد).
3. **کانونِ آیه:** کلیک روی آیه → روشن‌گرهایش در سراسر نقشه روشن می‌شوند (کمان‌های
   بینا‌سوره‌ای) و **پنل شاهد** باز می‌شود: متن آیه + هر روشن‌گر + ریشه‌های مشترکِ
   هایلایت‌شده در هر دو. کلیک روی روشن‌گر = کانونِ تازه («دنبال‌کردنِ نخ»).

### نشانه‌های صداقتِ بصری
- ضخامت یال ∝ وزنِ شاهد؛ زیر هر پیوند تنها توجیهِ مجاز: ریشه‌های مشترک.
- ۱٬۸۲۰ آیه‌ی بدونِ شاهد، کم‌نور و صریحاً علامت‌گذاری‌شده — امتناع دیده می‌شود.

### رندر
Sigma.js (WebGL) برای روانیِ گرافِ آیه‌مقیاس؛ مختصات از `build_graph_layout.py`.

## ۶) راهبردِ آزمون

- **بک‌اند (pytest):**
  - `/api/interpret/2:255` باید ۷:۹۷ را با ریشه‌ی مشترکِ نوم برگرداند.
  - پرچمِ `cross_sura` درست محاسبه شود.
  - آیه‌ی بدونِ شاهد (نمونه از آن ۱۸۲۰ تا) فهرستِ خالی برگرداند.
  - `/api/graph/communities` هر ۱۱۴ سوره را با مختصات برگرداند.
- **گام ساخت:** `validate_evidence_index.py` — بازتولیدِ بایت‌به‌بایت + جفت‌های مرجع.
- **فرانت (سبک):** آزمونِ رندرِ بی‌خطای پوسته + smoke برای کلاینت API + ثبت‌شدنِ ماژول.

## ۷) خارج از محدوده (YAGNI، برای فازهای بعد)

- ماژول‌های دیگرِ سکو (کاوش مفهوم، اطلس ریشه، میز پژوهش) — فقط *قرارداد* را آماده
  می‌کنیم، خودشان را بعداً می‌سازیم.
- احراز هویت، استقرار ابری، چندکاربری.
- هرگونه ترجمه/تفسیر/معنای بیرونی — مغایر قانون اساسی.

## ۸) معیارهای موفقیت

1. کاربر از صورت‌فلکی تا کانونِ یک آیه و دیدنِ روشن‌گرهایش با شاهدِ ریشه‌ی مشترک
   می‌رسد — روان و فوری.
2. جفت‌های مرجع (نوم، شرق/غرب، زیغ) در رابط دیده می‌شوند.
3. افزودنِ یک ماژولِ آزمایشیِ خالی فقط با دو فایل (روتر + ماژول فرانت) ممکن است،
   بی‌دست‌زدن به هسته — اثباتِ توسعه‌پذیری.
4. گام ساخت بایت‌به‌بایت بازتولیدپذیر است و امتناع (آیاتِ بی‌شاهد) صریحاً نمایش
   داده می‌شود.
