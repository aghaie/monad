**تاریخ:** ۲۰۲۶/۰۷/۱۰ — **نقش سند:** Chief System Architect

## ۰. تعریف محصول (پاسخ سؤال ۱)

**Monad v1 = موتور خودتفسیری قرآن (Minimum Viable Discovery Engine)** با دو قابلیت:

1. **Query (تعیّنی، آنی):** برای هر آیه یا ریشه، بر پایهٔ شاخص‌های اعتبارسنجی‌شدهٔ موجود، پاسخِ سندمحور برمی‌گرداند: آیه‌های توضیح‌دهنده، همسایگی معنایی ریشه، قوانین شرطی مرتبط — همه با ردهٔ اطمینان و provenance کامل.
2. **Discover (پروتکل ۹مرحله‌ای، ناهم‌زمان):** برای هر ریشه، Discovery Protocol v1 موجود (فریز v0.1.0، ۸۶ تست) را اجرا می‌کند و Knowledge + RFC تولید می‌کند.

| | مشخصات |
|---|---|
| **ورودی** | یکی از: `root` (باکوالتر یا عربی)، `ayah` (سوره:آیه)، `root-set` (چند ریشه) |
| **خروجی** | شیء `Answer` (برای Query) یا `RFC` (برای Discover) — هر دو JSON با: evidence[]، ردهٔ اطمینان (صریح/قوی/محتمل/نامشخص)، زنجیرهٔ provenance تا مختصات توکن، و فیلد `UNKNOWN` صریح وقتی شواهد کافی نیست |
| **کاری که نمی‌کند** | ترجمه، تفسیر کلامی، فتوا، ادعای اعجاز — خارج از دامنه (منشور، مادهٔ VI) |

هر پاسخ Monad v1 فقط از این چهار منبع اعتبارسنجی‌شده مشتق می‌شود:
`crossref_index.json` (L7) · `root_lexicon.json` (L3) · `evidence_index.json` + `stability.json` (L8) · `laws_verified.json` (L12) · و برای Discover: موتور `engine/` موجود.

**سه حلقه:**
- **Core** — بدون آن موتور کار نمی‌کند. فقط چیزهای عبورکرده از آزمون.
- **پلاگین‌های استاندارد (فعال در v1)** — اعتبارسنجی‌شده ولی حذف‌شدنی؛ موتور بدون آن‌ها هم پاسخ می‌دهد.
- **پلاگین‌های دروازه‌دار (آینده)** — هر چیزی که هنوز فرضیه است. اتصال فقط پس از عبور از دروازهٔ اعتبارسنجی (§۷).

## ۲. Pipeline Diagram (پاسخ سؤال ۲)

هر مرحله فقط یک مسئولیت دارد (§۵). دفاع‌پذیری هر مرحله با یافتهٔ پشتوانه‌اش مشخص شده.

```
Input (root | ayah | root-set)
  ↓
[1] Normalization ────────── باکوالتر↔عربی، حل مختصات (سوره،آیه)
  │                          پشتوانه: داربست مجاز منشور (Tanzil + QAC + نگاشت باکوالتر)
  ↓
[2] Primitive Extraction ─── آیه→توکن‌ها→ریشه‌ها (morphology)؛ وزن‌دهی ریشهٔ نادر (باند df [3,40])
  │                          پشتوانه: L3 (معنا در ریشه است، p=0.048) + L1/L4 (پایین‌تر و بالاتر از ریشه معنا نیست)
  ↓
[3] Evidence Retrieval ───── همسایه‌های شبکه (L6/L7)، همسایگی ریشه (L8)، قوانین منطبق (L12)
  │                          پشتوانه: L6 (~۱۰× روی محتوای نادر، p=0.005)، L7 (~۳×)، L8 (~۱۰×)
  ↓
[4] Discovery (اختیاری) ──── فقط مسیر Discover: پروتکل ۹مرحله‌ای؛ کارگرها PROPOSED،
  │                          فقط verify قطعی ACCEPTED می‌سازد (قاعدهٔ R1)
  ↓
[5] Confidence ───────────── نگاشت به صریح/قوی/محتمل/نامشخص؛ UNKNOWN وقتی شواهد زیر آستانه
  │                          پشتوانه: رده‌بندی مصوب منشور + آستانه‌های verify موجود (۳٫۰/۱٫۸)
  ↓
[6] Output ───────────────── Answer/RFC + provenance تا مختصات توکن؛
                             برچسب فارسی فقط اینجا و قرنطینه‌شده (پسااشتقاق)
```

**قید معماری:** مرحلهٔ ۴ تنها مرحلهٔ غیرتعیّنی است و خروجی‌اش بدون عبور از verify هرگز به Output نمی‌رسد. مراحل ۱–۳ و ۵–۶ تعیّنی و بایت‌به‌بایت بازتولیدپذیرند.

## ۵. اصل Single Responsibility (پاسخ سؤال ۵)

قواعد اجباری، برگرفته از انضباط موجود موتور:

1. **Normalizer** فقط نویسه/مختصات را حل می‌کند — هیچ معنایی تولید نمی‌کند.
2. **PrimitiveExtractor** فقط ریشه استخراج و وزن‌دهی می‌کند — هیچ رابطه‌ای نمی‌سازد.
3. **EvidenceRetriever** فقط بازیابی می‌کند — هیچ ادعایی نمی‌سازد و رتبهٔ اطمینان نمی‌دهد.
4. **کارگرها (observe/hypothesis/attack/reduce)** فقط پیشنهاد می‌دهند (`PROPOSED`) — تفسیر و قطعیت ممنوع.
5. **verify** تنها نقطهٔ تبدیل پیشنهاد به Knowledge است — خودش evidence جدید نمی‌سازد.
6. **ConfidenceReporter** فقط نگاشت نمره→رده انجام می‌دهد — محاسبهٔ آماری نمی‌کند.
7. **Output/Gloss** فقط قالب‌بندی و برچسب فارسیِ قرنطینه — هیچ استنتاجی نمی‌کند.

نقض هر یک = باگ معماری. (کشف و تفسیر هرگز در یک مرحله نیستند: کشف در ۳–۴، داوری در verify، بیان در ۶.)

## ۶. Engine API — قرارداد عمومی (پاسخ سؤال ۶)

بدون کد؛ هر قرارداد = ورودی، خروجی، تضمین، حالت خودداری.

| API | ورودی | خروجی | تضمین‌ها |
|---|---|---|---|
| `normalize(ref)` | متن عربی/باکوالتر یا «سوره:آیه» | `NormalizedUnit` | تعیّنی؛ خطای صریح روی مرجع نامعتبر |
| `primitives(unit)` | NormalizedUnit | `Root[]` با وزن نادری | فقط ریشه‌های QAC؛ توکن‌های بی‌ریشه گزارش می‌شوند نه حذف خاموش |
| `relate(ayah)` | مختصات آیه | `Relation[]` (آیه‌های توضیح‌دهنده از crossref) | مرتب‌سازی پایدار؛ **هشدار طول‌آیه در هر پاسخ درج می‌شود** (اغتشاش شناخته‌شدهٔ L7) |
| `neighborhood(root)` | ریشه | `Neighborhood` | اگر ریشه کم‌شاهد است → `UNKNOWN` با آستانهٔ اعلام‌شده |
| `laws(root \| root-set)` | ریشه(ها) | `Law[]` از ۳۸ قانون | فقط قوانین q≤0.031؛ جهت‌دار بودن حفظ می‌شود |
| `evidence(claim_id)` | شناسهٔ Answer/Knowledge/Law | `Evidence[]` | هر قلم با مختصات چهارتایی؛ P1 |
| `trace(claim_id)` | شناسه | زنجیرهٔ Provenance تا evidence | اگر زنجیره ناقص است، خطا (دروازهٔ P2) نه پاسخ ناقص |
| `confidence(claim_id)` | شناسه | یکی از صریح/قوی/محتمل/نامشخص + عدد پشتوانه | نگاشت ثابت و نسخه‌دار (آستانه‌های ۳٫۰/۱٫۸ ثبت‌شده) |
| `counterEvidence(claim_id)` | شناسه | خروجی مرحلهٔ attack + بازیابی معکوس (مثلاً reverse_support قانون) | «یافت نشد» = پاسخ معتبر، نه سکوت |
| `validate(claim)` | ادعای ساخت‌یافته | گزارش ValidationHarness: baseline/null/leakage/held-out | همان دروازه‌ای که پلاگین‌ها باید از آن عبور کنند (§۷) |
| `discover(unit)` | ریشه (v1: دامنهٔ quran-root) | `run_id` سپس `RFC` | run_id محتوامحور؛ اجرای مجدد همان ورودی = همان نتیجه |

قواعد سراسری API: (۱) هر پاسخ فیلد `tier` و `provenance` دارد؛ (۲) `UNKNOWN` پاسخ درجه‌یک است؛ (۳) هیچ API ورودی بیرونی (ترجمه/تفسیر) نمی‌پذیرد؛ (۴) نسخهٔ پروتکل در هر پاسخ درج می‌شود.

## ۷. Plugin Architecture (پاسخ سؤال ۷)

**قرارداد پلاگین:** هر پلاگین = `manifest (فرضیه + دادهٔ لازم) + build + validate + گزارش`. اتصال به Core فقط پس از عبور از **دروازهٔ استاندارد** — همان `validate()`: بیس‌لاین + null جایگشتی + کنترل نشتی + held-out + بازساخت بایت‌به‌بایت. پلاگین رد‌شده در حلقه می‌ماند و به Core دست نمی‌زند. پلاگین‌ها فقط **می‌افزایند** (فیلد/endpoint جدید)، هرگز رفتار Core را تغییر نمی‌دهند.

| پلاگین | فرضیه‌ای که پیاده می‌کند | دادهٔ لازم | آزمایش پیش از اتصال | به Core چه می‌افزاید |
|---|---|---|---|---|
| **L12-Laws** (فعال) | ساخت‌های شرطی، قوانین جهت‌دار کدگذاری می‌کنند | نشانگرهای COND/RSLT در monad.db | ✅ انجام شده (null=۲۰۰۰، FDR، p=0.0005) | `laws()` |
| **Persian-Gloss** (فعال) | — (سیاست، نه فرضیه) | glosses.json قرنطینه | ✅ سیاست مصوب؛ چک قرنطینه (فقط خروجی) | برچسب فارسی روی خروجی |
| **L10-Audit** (فعال) | ادعای ۴:۸۲ ممیزی‌پذیر است | contradiction_audit | ✅ انجام شده | endpoint ممیزی تناقض |
| **L11-Style** (فعال) | ساختار سبکی سنجش‌پذیر است | جدول‌های stylometry | ✅ (بدون ادعای اعجاز — UNKNOWN می‌ماند) | endpoint سبک‌سنجی توصیفی |
| **L9-Facets** (دروازه‌دار) | هر ریشه وجوه متمایز دارد | root/ayah_dossiers | پالایش هر-وجه + دونیمه به‌ازای وجه، p<0.05 سراسری پس از تصحیح | فیلد `facets` در `neighborhood()` |
| **Names-Axis** (دروازه‌دار) | نام‌های الهی محور معنایند (تنزل‌یافته) | L2_names + آزمون **غیرتوزیعی** جدید | باید عملیاتی‌سازی ساختاریِ جدید، بیس‌لاین و null را شکست دهد (دو آزمون قبلی رد شدند) | محور نام روی `neighborhood()` |
| **Word-Forms** (دروازه‌دار) | صورت واژه فراتر از ریشه معنا دارد | treebank نحوی (QAC v0.4 ندارد) | تفکیک صورت > بیس‌لاین ۶۲٫۱٪ با کنترل ریشه | لایهٔ صورت در `primitives()` |
| **Muhkam-B2** (دروازه‌دار) | محکم→متشابه جهت تفسیر دارد | عملیاتی‌سازی «وضوح» + شبکهٔ L6 | تعریف سنجش‌پذیر وضوح + null جایگشتی جهت‌دار | جهت‌دهی رتبهٔ `relate()` |
| **Self-Translation** (دروازه‌دار) | شبکه برای خودترجمه کافی است (مادهٔ A، اثبات‌نشده) | L3+L6+L8 | معیار موفقیت هنوز تعریف نشده — اول باید آزمونش طراحی و تصویب شود | خروجی ترجمهٔ درونی |
| **Legacy-Revalidation** (دروازه‌دار) | هر قلم از ~۲۴۵ گزارش قدیمی (مثلاً سیاق فرایند ۵۲٫۷٪) | monad.db | بازآزمایی کامل زیر انضباط فعلی، قلم‌به‌قلم | بسته به قلم |

## ۸. بازبینی از دید توسعه‌دهنده — چه چیزهایی کم است (پاسخ سؤال ۸)

یک برنامه‌نویس جدید با این سند + مخزن می‌تواند شروع کند، ولی این شکاف‌ها باید در Milestone M0/M1 بسته شوند (همه از بک‌لاگ و ممیزی موجود، نه ایدهٔ جدید):

1. **پراکندگی خروجی‌ها:** شاخص‌های Core در `generated/layers/` و evidence موتور در `store/` جدا هستند و شِمای مشترک ندارند → v1 باید یک «قرارداد خواندن» واحد (loader با manifest و `input_sha256`) تعریف کند.
2. **شِمای Answer وجود ندارد:** Query امروز محصول اسکریپت‌هاست نه سرویس؛ شِمای JSON `Answer` باید نوشته و در تست golden ثبت شود.
3. **`two_half_stability` فقط چک حضور است** (null_p=None) — در هر خروجی باید همین‌طور برچسب بخورد؛ تبدیل به آزمون واقعی در بک‌لاگ v2 است، نه v1.
4. **اغتشاش طول در هاب‌های L7:** تا نرمال‌سازی طول انجام نشده، `relate()` باید هشدار ثابت درج کند (در قرارداد §۶ گنجانده شد).
5. **مقیاس ۱ → ۱٬۶۴۲ ریشه برای Discover:** اجرای دسته‌ای، حجم golden (~۱GB)، dedup یال‌های DAG، و منطق P3 — همه در بک‌لاگ مهندسی موجودند و در M4 آدرس داده می‌شوند.
6. **`README.md` با واقعیت مخزن نمی‌خواند** و `methodology.md` §6 رده‌بندی قدیمی دارد → به‌روزرسانی سندی در M0.
7. **فایل‌های مرده:** `monad.db` صفربایتی ریشه، پوشه‌های خالی `data/ graph/ experiments/ prompts/` → پاک‌سازی در M0.

## ۹. Build Order (ترتیب ساخت)

هر گام فقط بر گام قبلی تکیه دارد؛ چرخهٔ «بساز → راستی‌آزمایی → گزارش → کامیت» برای هر گام برقرار است.

```
M0 پاک‌سازی و انجماد پایه
 └► M1 Core Query (فقط‌خواندنی روی شاخص‌های موجود)
     └► M2 Provenance و Confidence یکپارچه
         └► M3 Interface (CLI + HTTP) و شِمای Answer نهایی
             └► M4 Discover در مقیاس (دسته‌ای روی ریشه‌ها)
                 └► M5 Plugin SDK + پلاگین‌های فعال v1
```

## ۱۱. Definition of Monad v1 (تعریف نهایی / Definition of Done)

Monad v1 آماده است وقتی و فقط وقتی:

1. برای **هر یک از ۶٬۲۳۶ آیه**، `relate()` پاسخ سندمحور با provenance و هشدار طول می‌دهد.
2. برای **هر یک از ۱٬۶۴۲ ریشه**، `neighborhood()` یا پاسخ ردهبندی‌شده می‌دهد یا `UNKNOWN` صریح.
3. `laws()` دقیقاً ۳۸ قانون تأییدشده را با evidence سرو می‌کند — نه بیشتر.
4. `discover()` برای حداقل ۵۰ ریشهٔ قوی، RFC بازتولیدپذیر تولید کرده است.
5. **هیچ مسیر کدی** در Core از `external/`، ترجمه، تفسیر یا مسیر قدیمی ۳۰-موتوره نمی‌خواند (تست ایستا).
6. هر پاسخ `trace()`پذیر تا مختصات توکن است؛ ادعای بدون provenance = خطای اجرا.
7. کل Query تعیّنی است: دو اجرای یکسان = دو خروجی بایت‌به‌بایت یکسان (golden).
8. چهار پلاگین فعال از راه SDK وصل‌اند و حذفشان Core را نمی‌شکند.
9. هیچ فرضیهٔ دروازه‌دار (نام‌ها، وجوه، B-2، خودترجمه، legacy) در هیچ مسیر Core حضور ندارد.

**آنچه v1 نیست:** کامل نیست، مفسر نیست، مترجم نیست. موتوری است که *فقط آنچه را امروز از آزمون عبور کرده* سرو می‌کند و برای هر ادعای آینده یک دروازهٔ اعتبارسنجی یکسان دارد.
